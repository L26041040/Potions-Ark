## 給 Claude Code 的指令

你要實作「Potions 二店選址倉庫」：Potions 股東共用的房屋收藏與討論網站。3 到 6 人使用，目標是最快交付、保持簡單。

### 一、動工前先讀

1. `docs/spec/mvp-spec.md`：規格 v2.0，唯一的依據。驗收標準是第 7 節的 V1–V13。
2. `GLOSSARY.md`：名詞表。畫面文字用這裡的名詞。規格 v2.0 沒用到的名詞（例如規劃、樓層與用途）不必實作。
3. `docs/adr/`：只有 ADR-0001（共享密碼＋暱稱）仍適用。ADR-0002 只剩「用 Neon、不用 Supabase」適用。ADR-0003 已不適用，不要照它做。
4. 不要讀 `docs/spec/appendix-591.md`，它已不屬於規格。
5. 安裝 Next.js 之後，寫任何 Next.js 程式之前，先讀 `node_modules/next/dist/docs/` 裡對應的文件。這個版本與舊版差異很大，不要憑記憶寫。

### 二、原則

1. 主目標是找二店地點。網站裡不得有任何展演相關的欄位或必填項目。
2. 物件的詳細內容一律看原始網頁。不要解析刊登內容，不要下載或儲存任何照片。
3. 規格沒寫的功能不做。這次的方向是減法；想加任何東西之前先問。

### 三、權限邊界

超出大哥這次給的授權範圍時，**不得**做以下任何一件事：

- 建立 Vercel 專案或資料庫，或主動觸發部署。
- 建立或推送 `main` 分支。開發只在這次工作階段指定的開發分支上進行。
- 開 pull request。

以下幾件事不論授權範圍，一律不做：

- 升級方案、購買任何東西、變更 repo 可見性。
- 設定、讀取或索取 Vercel 上的 `SITE_PASSWORD`。本機環境檔裡的測試密碼不在此限。
- 登入已部署的站，或在已部署的站上建立資料。
- 建立 Blob store 或任何儲存照片的服務。
- 建立遠端瀏覽器、代理、網頁鏡像或截圖服務。網站不能嵌入時，就是另開視窗。

專案連上 Vercel 之後，推送開發分支會自動產生預覽部署，這不算違反上述規定。

程式庫是公開的。不得提交密碼、`.env` 檔、真實物件資料。

### 四、容易做錯的地方

- **建立專案**：repo 根目錄已有其他檔案，`create-next-app` 會拒絕直接在根目錄建立。在暫存子資料夾建立後把檔案搬到根目錄。使用 TypeScript、Tailwind、App Router、npm。旗標以當下 `create-next-app --help` 為準。
- **Cache Components**：若腳手架預設開啟而且卡住進度，直接在 `next.config` 關掉，不要耗時間。
- **登入檢查**：攔截檔（這個版本叫 `proxy.ts`）只負責把未登入的頁面請求導向登入頁。每一個 Server Action 與每一個讀資料的伺服器元件，第一步都要自己確認登入狀態；Server Action 是任何人都能直接 POST 的端點。
- **資料庫**：`pg` 連線池，延遲建立。全部用參數化查詢。Schema 檔可重複執行、只增不減，在建置指令中套用；在 Vercel 上沒有連線字串時要失敗，本機沒有時略過。
- **網址狀態**：瀏覽區的開關由網址的 `?item=` 推導，用 `history.pushState`／`replaceState` 配合 `useSearchParams`。開啟新增一筆瀏覽紀錄，上一間／下一間不新增。不要用 parallel routes 或 intercepting routes。
- **嵌入**：iframe 要加 `sandbox`（允許腳本、同源、表單、彈出視窗，但不允許導走最上層頁面）與 `referrerpolicy="no-referrer"`。能否嵌入的判斷規則照規格 4.1，在伺服器讀取頁面時一併完成。
- **外部視窗**：「開啟原始網頁」用固定的視窗名稱開啟，連續使用時沿用同一個視窗。
- **封面**：一般的 `<img>`，加 `loading="lazy"` 與 `referrerpolicy="no-referrer"`，載入失敗時改顯示名稱色塊。不要用 `next/image`。
- **抓取**：照規格 6.5 的四條限制。被擋下就停，絕不嘗試繞過。
- **時間**：畫面上的時間以台北時間顯示。

### 五、本機驗證

開發機拿不到 Neon 的憑證：

- 資料庫用本機 PostgreSQL（開發機已安裝 16 版，需自行啟動）。若沒有，選一個不需要雲端憑證的替代做法並在回報中說明。
- 用一個只存在本機環境檔（不提交）的測試密碼登入。
- 寫一支簡短的瀏覽器腳本 `scripts/smoke.cjs`，用開發機預先安裝的 Playwright（只能用 `require` 載入，不要另外安裝），對本機伺服器把 V1–V13 走一遍。
- 嵌入與封面需要連到真實網站。開發機若連得到 591，手動確認一次右側是否真的顯示出原始網頁，並把結果寫進回報；連不到就註明「待大哥在正式站確認」。不要為此寫自動化測試。

不要求單元測試。

### 六、執行順序

照規格 8.1 的六步，一次做一步，每步做完自己驗證再往下。每一步完成後提交一次並推送到開發分支。

完成的條件：

1. lint、型別檢查、建置全部通過。
2. 腳本走完 V1–V13，並在回報中逐條列出「通過」「未通過」或「需要正式環境才能驗」。

### 七、部署

只有授權範圍包含部署時才做，步驟照規格 8.2。其中標示「大哥」的步驟你做不了，要停下來一次講清楚該點哪裡、填什麼，等大哥回覆完成後再繼續。

### 八、遇到狀況怎麼辦

- 規格與實際行為衝突（例如平台限制變了）：選最簡單、不擴大範圍的替代做法，做完在回報中說明。
- 會改變規格內容的事：停下來問，不要自己決定。

### 九、完成後的回報

用繁體中文：

1. V1–V13 每一條的結果。
2. 與規格不同的地方及理由。
3. 591 嵌入的實測結果，或註明尚未實測。
4. 需要大哥操作或決定的事項，一次列完。
5. 已知問題，照實寫。
