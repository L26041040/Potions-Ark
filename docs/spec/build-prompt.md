## 給 Claude Code 的指令

你要實作並部署「Potions 二店選址倉庫」：Potions 股東共用的 591 收藏與討論工具。3 到 6 人使用，目標是最快交付可直接使用的網站。

### 一、依據

- `docs/spec/mvp-spec.md` v2.4 與 GitHub Issues #1–#5 是依據；v2.2、v2.4 功能細節與驗收以 Issue 為準，v2.3 以規格第 5 節 16–19 項為準。
- 名詞表與 ADR 只作背景參考；與規格衝突時以規格為準。`appendix-591.md` 不必讀。
- 寫 Next.js 程式前先讀 `node_modules/next/dist/docs/` 對應文件，這個版本與舊版差異大。

### 二、原則

1. 沒有登入。暱稱存在瀏覽器本地儲存，資料存在伺服器端的共享儲存。
2. 使用者零設定：部署、Blob store、環境變數都由你用 Vercel 與 GitHub 工具完成，不要推回給大哥。真的卡在無法自動完成的帳號授權時，才提出一次最小必要操作。
3. 不購買、不升級任何付費方案。
4. 只解析 591 店面出租頁的公開資料（標題、照片、租金、坪數、樓層、地址、公開聯絡資訊）；其他網站只取封面。591 照片直接顯示原站網址，不複製；只有股東上傳的照片會存進 Blob。
5. 規格沒寫的功能不做。

### 三、不做

- 代理瀏覽器、遠端瀏覽器、網頁鏡像、截圖服務。
- 以偽裝瀏覽器等方式繞過任何網站的防機器人機制。
- 登入、帳號、權限、排程、通知、管理後台。

### 四、容易做錯的地方

- **建立專案**：repo 根目錄已有檔案，在暫存子資料夾用 `create-next-app` 建立後搬回根目錄。
- **資料儲存**：Blob 存取只在 `lib/store.ts`（資料）與 `lib/photos.ts`（上傳照片）兩個模組。寫入用「讀取 → 變更 → 條件寫入，衝突就重試」；在 Vercel 上找不到 Blob 設定要報錯，本機沒有時改用本機檔案。
- **外部網址讀取**：照規格 6.4，DNS 解析結果也要檢查，避免存取內部網路。
- **iframe**：`sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox"` 加 `referrerpolicy="no-referrer"`。
- **外部視窗**：「開啟原始網頁」用固定視窗名稱，連續使用沿用同一個視窗。
- **網址狀態**：`?item=` 用 `history.pushState`／`replaceState` 控制，返回鍵關閉瀏覽區。
- **時間**：以台北時間顯示，避免伺服器與瀏覽器時區不同造成畫面不一致。
- **試算表匯入**：試算表含聯絡資訊，只能放在暫存區，不得提交到 repo；先用 `--dry-run` 核對，再正式匯入，匯入後比對備份確認既有資料完整。

### 五、驗證與部署

1. 本機：lint、型別檢查、建置通過；用預先安裝的 Playwright（以 `require` 載入）寫一支腳本把主要流程走一遍。
2. 部署：建立 Vercel 專案（連結本 repo）、建立私人 Blob store 並接上專案、推送開發分支觸發正式部署。
3. 線上驗收：照規格第 7 節逐條確認。線上測試留下的測試物件在完成後刪除。

### 六、完成後回報

1. 正式網址。
2. Commit 與分支。
3. 已完成的功能與驗收結果。
4. 591 嵌入實測結果。
5. 未完成的項目。
6. 是否有必須由大哥處理的阻礙。
