## 1. 定位

Potions Magic Bar 股東共用的「591 收藏與討論工具」，用來找二店地點。展演空間只是可能的附加規劃，網站裡沒有相關欄位，要談就寫在備註或留言。

核心流程：**貼網址 → 收藏物件 → 右側觀看原始網頁 → 討論 → 修改狀態**。

成功標準：拿到網址後直接貼 591 連結，就能開始和股東討論。

## 2. 使用者零設定

- 開啟網址即可使用，**沒有登入**、沒有共享密碼、沒有帳號與權限，所有人權限相同。
- 暱稱在第一次需要識別身分時（收藏、改狀態、寫備註、留言、刪除）輸入，存在該瀏覽器的本地儲存。可以隨時更改。
- 資料共用：所有人讀寫同一份資料，存在伺服器端的雲端儲存，不是瀏覽器本地儲存。重新整理即同步，重新部署不會清空。
- 部署、資料儲存、環境變數全部由開發代理用現有的 Vercel 與 GitHub 授權自動完成；不要求大哥建立資料庫、複製權杖、設定環境變數或購買任何方案。
- 已知取捨：任何拿到網址的人都能檢視與修改資料。網站不讓搜尋引擎收錄，網址請只在股東間分享。

## 3. 介面

全站繁體中文，網站名稱「Potions 二店選址倉庫」，時間以台北時間顯示。

### 3.1 倉庫

- 上方：貼網址輸入框與「收藏」（最顯眼）、批量收藏、手動新增、暱稱。收藏或新增後留在倉庫，不自動開啟面板（#1）。
- 工具列：搜尋、狀態篩選、圖庫／列表切換。
- 狀態篩選：全部（不含不考慮，預設）、未討論、待確認、確定考慮、不考慮、回收桶，另有獨立的「已失效」（#4）。
- 排列固定新的在前。
- 圖庫：卡片顯示封面（有才顯示，否則名稱色塊）、名稱、簡單資訊、狀態；連結已失效時加紅色「已失效」，無法確認時加低調的「無法確認」。
- 列表：小封面、名稱、簡單資訊、狀態。
- 搜尋：比對名稱、簡單資訊、地址、重要備註。

### 3.2 桌面版：左倉庫、右瀏覽

- 開啟物件後，左側 1/3 是倉庫（仍可捲動與點選，選中者標示），右側 2/3 是物件瀏覽區。
- 瀏覽區最上方是控制列：上一間／下一間、名稱、四個狀態按鈕、開啟原始網頁、Google Maps（有地址才顯示）、編輯、刪除（或還原）、關閉。
- 控制列：上一間／下一間、重新取得照片與資訊、編輯、刪除（或還原）、嵌入原始網頁（選配）、收合討論、關閉。
- 控制列下方左右並排：左為本站原生預覽，由上到下是照片輪播（可放大）、名稱、月租金／坪數／樓層／地址、連結狀態、四種狀態、開啟原始網頁與 Google Maps；右為討論區，寬度固定、獨立捲動。嵌入原始網頁是選配切換，預設關閉（#3）。
- 討論區由上到下：重要備註、留言輸入框、留言與狀態異動紀錄（新的在上）。
- 上一間／下一間依目前篩選與搜尋結果切換，到頭尾停用。開著的物件即使因改狀態而不符合篩選，也保留在清單中直到關閉。
- 關閉：X、Esc、瀏覽器返回鍵。關閉後倉庫回到全寬，剛才看的物件捲回畫面內。
- 開啟物件時網址帶 `?item=<物件 id>`，就是該物件的直達連結。

### 3.3 手機版

- 倉庫兩欄圖庫或列表。
- 點物件進入全螢幕檢視，順序同桌面預覽：照片輪播、名稱、資訊、連結狀態、狀態按鈕、明顯的「開啟原始網頁」（另開分頁）、Google Maps，之後是重要備註與留言。
- 手機不嵌入原始網頁。

## 4. 原始網頁（v2.2 起 iframe 為選配，預設關閉；以下保留判斷規則）

### 4.1 能否嵌入的判斷

- 收藏時伺服器讀取該網址一次，同時檢查回應標頭：有 `X-Frame-Options`，或 `Content-Security-Policy` 的 `frame-ancestors` 不含 `*`，就判定不能嵌入（不論狀態碼）。
- 完全讀不到時，`https` 網址預設嘗試嵌入，`http` 網址不嵌入。
- 編輯時可手動切換「在右側嵌入原始網頁」。

### 4.2 可以嵌入

- 右側直接顯示原始網頁。iframe 以 `sandbox` 禁止它把整個網站導走，並以 `referrerpolicy="no-referrer"` 不洩漏本站網址。

### 4.3 不能嵌入

- 右側顯示封面、名稱、簡單資訊、一句「這個網站不允許嵌入」與明顯的「開啟原始網頁」。
- 「開啟原始網頁」固定使用同一個外部視窗，擺在旁邊即可並排查看；切到下一間再按一次，旁邊的視窗就換成那一間。

### 4.4 591 實測結果（2026-11-21）

- 591 店面頁與住宅頁的回應沒有任何禁止嵌入的標頭；模擬瀏覽器框架請求（`Sec-Fetch-Dest: iframe`、跨站）也回 200。
- 用真實 Chromium 引擎嵌入時，瀏覽器**沒有**拒絕框架（同一頁的樂屋網則被瀏覽器以 `X-Frame-Options` 拒絕）。但 591 的防機器人機制把自動化瀏覽器（HeadlessChrome）擋成 403，因此無法在自動化環境看到框架內的實際畫面；以一般瀏覽器身分繞過該機制屬於規避網站防護，不做。
- 從 Vercel 新加坡節點讀取 591 頁面成功，名稱、封面、描述都能自動帶入。
- 結論：591 應可嵌入，最終畫面由真人瀏覽器在正式站確認。若不能顯示，在編輯中關閉嵌入即可改用 4.3 的方式。
- 樂屋、住商、永慶、好房網禁止嵌入，會自動走 4.3。

不建立代理瀏覽器、遠端瀏覽器或網頁鏡像。

## 5. 功能

1. **貼網址收藏。** 貼上的內容可夾雜文字，取第一個網址。伺服器讀取標題（當名稱）、封面圖片網址、一段描述（當簡單資訊）。讀不到不影響收藏：名稱改用貼上的其他文字，再沒有就用「來自 <網站> 的物件」。
2. **重複網址。** 網址去掉 `#` 片段、`utm_` 開頭與 `fbclid` 參數後，與某個未刪除物件相同，就直接開啟那個物件。不做其他去重。
3. **手動新增。** 只需名稱，可另填網址、地址、簡單資訊。
4. **編輯。** 名稱、簡單資訊、地址、來源網址、封面圖片網址、是否嵌入。
5. **四種狀態。** 未討論（預設）、待確認、不考慮、確定考慮。一鍵切換，同時自動記一筆「<暱稱> 將狀態從 A 改為 B」。
6. **重要備註。** 每個物件一段可隨時改寫的文字，按儲存才寫入，顯示最後更新者與時間。
7. **留言。** 顯示暱稱與時間，新的在上，只能新增。
8. **圖庫／列表切換、搜尋、狀態篩選。**
9. **上一間／下一間。**
10. **Google Maps 連結。** 有地址才顯示，開啟地圖搜尋。
11. **直達連結。** 每個物件有自己的網址。
12. **刪除與還原。** 刪除需確認，進回收桶，可還原。

v2.2 新增（詳見各 Issue）：

13. **批量收藏（#2）。** 一次貼入任意數量的網址（每行一個或整段 LINE 訊息），沒有筆數上限；分小批送出、整批一次寫入、寫入當下去重，顯示進度與成功（含需補填）、重複、失敗統計。
14. **本站原生預覽（#3）。** 591 店面出租頁讀取公開資料中的照片組、月租金、坪數、樓層、地址；其他網站只取封面。591 照片由瀏覽器直接向原站載入，不複製。可上傳照片或截圖（永久保存）、刪除上傳的照片、「重新取得照片與資訊」（只補空白欄位、保留上傳照片）。591 App 的分享連結（591.to）會解開成物件本身的網址。
15. **連結健康檢查（#4）。** 正常／已失效／無法確認／待檢查，獨立於股東狀態。下架（404、410 或頁面明確顯示下架）才是已失效；被擋、驗證頁、逾時一律是無法確認。開啟倉庫時在背景檢查超過 24 小時未檢查的物件（不考慮與回收桶除外），沒有排程。

v2.3 新增：

16. **預設篩選「未討論」。** 打開倉庫先看到還沒討論的物件；其他篩選一鍵切換。搜尋時若其他分類也有符合的物件，清單上方會提示並可一鍵切過去。
17. **591 真實標題。** 名稱優先取 591 頁面結構化資料（JSON-LD 的 Place 名稱），不只靠 og:title；「591」「591房屋交易網…」這類網站名稱與 591 的全站描述不會當成名稱或資訊。「重新取得」會修正這類名稱，但股東手動改過的名稱不動；讀取失敗時保留原名稱。
18. **聯絡資訊。** 每個物件一個可編輯的文字欄位（房仲公司、聯絡人、電話、LINE ID 等），詳細面板顯示，電話變成撥號連結、LINE ID 變成 LINE 連結，可用聯絡人、公司、電話（有無橫線皆可）搜尋。591 頁面公開顯示的資料會自動帶入：經紀人卡片上的身分、姓名、公司，以及刊登內文寫的電話與 LINE ID；只有按「打電話」才出現的號碼不讀。
19. **去重與試算表匯入。** 同一個 591 物件不論網址形式（加參數、手機版、591.to 分享連結解開後）都視為同一筆。股東試算表由 Claude Code 以授權的連接器讀取後，透過 `/api/import`（`scripts/import-sheet.mjs`）分批合併：先備份正式資料、依物件編號合併（含回收桶中的物件，合併後仍留在回收桶）、股東手動資料 > 試算表 > 自動抓取（名稱只是「591」等無效值時以試算表為準）、理由與備註完整附加到重要備註、不覆蓋股東的決策／備註／留言／照片、重跑不會重複。試算表原始資料不進 repo。

封面與 591 照片由瀏覽器直接向原站載入，不帶來源資訊；載入失敗時顯示名稱色塊或占位圖，並提示可上傳照片。

## 6. 技術架構

### 6.1 服務

| 服務 | 用途 | 費用 |
|---|---|---|
| Vercel（Hobby，現有方案） | 網站與伺服器端程式，區域 `sin1` | US$0 |
| Vercel Blob（私人 store） | 共享資料（整份資料一個 JSON 檔）與股東上傳的照片 | Hobby 內含額度內 US$0 |

- 不使用 Neon：它必須由大哥本人在 Vercel Marketplace 同意條款才能建立，違反零設定。
- Blob store 由開發代理用 Vercel 工具建立並接上專案，所需環境變數由 Vercel 自動注入。

### 6.2 程式

- Next.js（App Router）＋ TypeScript ＋ Tailwind CSS。
- 讀資料：首頁在伺服器端讀取整份資料交給畫面。寫資料：Server Action 讀取最新資料、套用變更、寫回，並把新的整份資料回傳給畫面。批量收藏與背景連結檢查改走一般 API 路由（`/api/add`、`/api/recheck`），因為 Next.js 對同一瀏覽器的 Server Action 一次只處理一個，長時間的工作會讓股東其他操作排隊。
- 照片上傳走 `/api/items/<id>/photos`（一次一張、上限 4 MB、以檔頭確認 JPEG／PNG／WebP、每物件 30 張、回收桶物件不可上傳）；照片由 `/api/photo` 提供，快取一天。
- Blob 存取只在兩個模組：`lib/store.ts`（資料）與 `lib/photos.ts`（上傳照片）。
- 寫入以條件寫入（資料自讀取後未被改動才寫入，否則重讀重試）避免兩人同時操作互相覆蓋；若儲存服務不支援，就在寫入前重讀最新資料，並接受極小的覆蓋機率。
- 本機開發沒有雲端憑證時，資料改存本機檔案；在 Vercel 上找不到 Blob 設定時直接報錯，不得退回本機檔案。
- 全站回應帶 `X-Robots-Tag: noindex, nofollow`。

### 6.3 資料

一個 JSON 檔，內含：

- `items`：`id`、`name`、`sourceUrl`、`coverUrl`、`info`、`address`、`embed`、`status`（`new`／`pending`／`rejected`／`shortlisted`）、`note`、`noteBy`、`noteAt`、`createdBy`、`createdAt`、`updatedAt`、`deletedAt`、`deletedBy`；v2.2 新增 `rent`、`area`、`floor`、`photos`（來源：原始刊登／上傳）、`health`、`healthAt`、`healthReason`；v2.3 新增 `contact`（聯絡資訊）與 `manual`（由人填寫、自動讀取不得覆蓋的欄位）。舊資料讀取時自動補預設值，不需搬移。
- 匯入前的備份存在同一個 Blob store 的 `<環境>/backups/<匯入代號>.json`，同一代號只保留第一份。
- `entries`：`id`、`itemId`、`kind`（`comment`／`status`）、`body`、`from`、`to`、`nickname`、`createdAt`。

### 6.4 讀取外部網址的安全限制

1. 只接受 `http`、`https`，最多跟隨 3 次轉址，每一跳重新檢查。
2. 拒絕 `localhost`、IP 位址形式的主機，以及 DNS 解析後為私有、迴環、鏈路本地等內部位址的主機，避免存取內部網路。
3. 逾時 6 秒，最多讀 1 MB，只解析 HTML（JSON 等其他內容只用於判斷連結狀態）。只有 591 自家的分享中繼頁會被解開成物件網址，其他網站的轉址目的地不會取代原本存的網址。
4. 使用固定且誠實的 User-Agent，不送 cookie，被擋下就停，不繞過。

讀取失敗時物件照樣建立。

### 6.5 部署

- Vercel 專案連結 GitHub repo，正式分支是 repo 的預設分支 `claude/optimistic-gates-9v9rmn`，推送即自動部署。
- 正式網址為 Vercel 產生的 `*.vercel.app` 網址。

## 8. 已知限制

- **Vercel Hobby 的商業用途條款。** Hobby 服務條款限定「personal or non-commercial use」，本工具屬公司內部用途，屬灰色地帶；依大哥「不購買付費方案」的指示使用 Hobby。Vercel 有權停用 Hobby 專案，日後若要確保穩定，升級 Pro（US$20／月）即可，程式不必改。
- **Blob 免費額度。** Hobby 每月約 2,000 次寫入、10,000 次讀取；超過時 Blob 會被停用最長 30 天。股東數人日常討論應在額度內，但大量操作有風險。每次收藏、改狀態、存備註、留言、刪除各算一次寫入。
