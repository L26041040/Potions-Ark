## 1. 定位與核心流程

這是 Potions 股東共用的「房屋收藏與討論網站」，不是房地產管理平台。

- 主目標：找 Potions 二店的地點。
- 展演空間只是可能的附加規劃，網站裡沒有任何展演相關的欄位或必填項目，要談就寫在重要備註或留言裡。

核心流程只有一條：

**貼入網址 → 收藏成物件 → 點選物件 → 查看原始房仲網頁 → 討論與分類**

物件的詳細內容（照片、租金、坪數、格局）一律看原始網頁，本站不複製、不解析、不保存。本站只負責三件事：把物件收在一起、讓股東看得到原始網頁、記下大家的狀態與討論。

## 3. 介面

全站繁體中文，網站名稱「Potions 二店選址倉庫」。

### 3.1 倉庫（左側）

- 沒有開啟物件時，倉庫佔滿整個畫面。
- 上方：貼網址輸入框（最顯眼）、手動新增、搜尋、狀態篩選、圖庫／列表切換、登出。
- 狀態篩選：全部（不含不考慮，預設）、未討論、待確認、確定考慮、不考慮、回收桶。
- 排列固定為新的在前。
- **圖庫**（預設）：每張卡片顯示封面、名稱、簡單資訊（一行，過長截斷）、狀態。沒有封面或封面載入失敗時，顯示名稱色塊。
- **列表**：每列顯示小封面、名稱、簡單資訊、狀態。
- **搜尋**：在瀏覽器端比對名稱、簡單資訊、地址、重要備註。
- 點任一物件，在右側開啟瀏覽區。

### 3.2 物件瀏覽區（右側，桌面）

開啟物件時畫面左右分割：左側倉庫約佔三分之一，仍可捲動與點選其他物件，選中的物件要標示出來；右側瀏覽區約佔三分之二。

右側由上到下三塊：

1. **控制列**：上一間／下一間、名稱、四個狀態按鈕、「開啟原始網頁」、「Google Maps」（有地址才顯示）、編輯、刪除、關閉。
2. **原始網頁**：嵌入的房仲網頁，或不能嵌入時的替代畫面。見第 4 節。
3. **討論區**：左半是重要備註，右半是留言。討論區可以收合，讓原始網頁佔滿高度。

互動規則：

- 上一間／下一間依倉庫目前的篩選與搜尋結果順序切換，到頭尾時按鈕停用。
- 關閉方式：X、Esc、瀏覽器返回鍵。關閉後倉庫回到全寬，剛才看的物件仍在畫面內。
- 開著的物件若因為改了狀態而不符合目前的篩選（例如在預設篩選下改成「不考慮」），瀏覽區保持開啟，直到股東關閉或切到別的物件。
- 開啟物件時網址帶 `?item=<物件 id>`，這就是該物件的直達連結。

### 3.3 手機

- 倉庫佔滿畫面，圖庫為兩欄。
- 點物件進入全螢幕的詳細檢視，由上到下：上一間／下一間與關閉、名稱、封面、簡單資訊、狀態按鈕、一顆明顯的「開啟原始網頁」（另開分頁）、Google Maps、重要備註、留言。
- 手機上不嵌入原始網頁。小螢幕上在網頁裡再捲一個網頁很難操作，直接另開分頁比較好用。

## 4. 原始網頁的嵌入

### 4.1 怎麼判斷能不能嵌入

網站能不能被嵌入，由對方伺服器的回應標頭決定，本站無法改變。

- 貼上網址新增物件時，伺服器本來就會讀那一頁一次（取標題與封面），同時看回應標頭，把結果記在物件上。
- 判斷規則：
  - 回應帶有 `X-Frame-Options`，或 `Content-Security-Policy` 的 `frame-ancestors` 不含 `*`：不能嵌入。
  - 讀取失敗、被擋、狀態碼不是 200，或網址不是 `https`：當作不能嵌入。
  - 其餘：可以嵌入。
- 編輯物件時可以手動切換「在右側嵌入原始網頁」。判斷錯了，或對方網站日後改了設定，股東自己關掉或打開即可。

### 4.2 可以嵌入時

- 右側中間直接顯示原始網頁，股東可以在裡面捲動、看照片、點頁內的連結。
- 控制列的「開啟原始網頁」仍然在，隨時可以另開視窗。
- 嵌入的網頁不能把整個網站導走，本站也不會把物件的直達連結透露給對方網站（以 iframe 的 `sandbox` 與 `referrerpolicy` 設定達成）。

### 4.3 不能嵌入時

- 右側中間顯示替代畫面：封面、名稱、簡單資訊、一句說明「這個網站不允許嵌入」，以及一顆明顯的「開啟原始網頁」。
- 「開啟原始網頁」固定開在同一個外部視窗。股東把那個視窗擺在旁邊，之後每按一次上一間／下一間再按「開啟原始網頁」，旁邊的視窗就換成那一間，達到並排查看。
- 狀態、重要備註、留言照常在本站操作，不受影響。

### 4.4 目前查到的情況

2026-11-21 只檢查了回應標頭，**還沒有在真實瀏覽器裡實際嵌入測試**。

| 網站 | 回應標頭 | 預期 |
|---|---|---|
| 591 店面出租頁、住宅出租頁 | 沒有任何禁止嵌入的標頭，頁面原始碼也沒看到跳出框架的程式 | 可以嵌入 |
| 信義、21 世紀、太平洋（首頁） | 沒有禁止嵌入的標頭 | 可能可以，物件頁未查 |
| 樂屋、住商、永慶 | `X-Frame-Options: SAMEORIGIN` | 不能嵌入 |
| 好房網 | `frame-ancestors 'self'` | 不能嵌入 |

591 是主要來源，依標頭看可以嵌入，但是否能在框架內正常顯示（例如對方的防機器人機制、瀏覽器對第三方 cookie 的限制）要實作後在瀏覽器確認。591 也可能隨時加上禁止嵌入的標頭，屆時新物件會自動走 4.3 的替代畫面。

### 4.5 明確不做

不建立遠端瀏覽器、代理瀏覽器、網頁鏡像或截圖服務。不能嵌入就是另開視窗。

## 5. 第一版必要功能

1. **貼網址新增物件。** 貼上的內容可以夾雜文字，取其中第一個網址。
2. **手動新增。** 沒有網址也能新增，只需要填名稱。
3. **自動取得基本資料。** 嘗試讀取標題（當名稱）、封面圖片網址、一段描述（當簡單資訊）。讀不到不影響收藏：名稱改用貼上的文字，再沒有就用「來自 <網站主機名> 的物件」。
4. **手動編輯。** 可編輯名稱、簡單資訊、地址、來源網址、封面圖片網址、是否嵌入。
5. **四種狀態。** 未討論（新物件的預設）、待確認、不考慮、確定考慮。任何股東一鍵切換，沒有審核。被別人租走的物件改成「不考慮」再留言說明。
6. **圖庫／列表切換。**
7. **重要備註與股東留言。**
   - 重要備註：每個物件一段可隨時改寫的文字，顯示最後更新者與時間。它就是名詞表裡的「目前結論」。
   - 留言：依時間排列，顯示暱稱與時間，新的在上。只能新增。
   - 改狀態時自動在留言區記一筆「<暱稱> 將狀態從 A 改為 B」。
8. **Google Maps 連結。** 有填地址才顯示，以地址組成地圖搜尋網址，不接地圖 API。
9. **共享密碼與暱稱。** 一組共享密碼加自填暱稱進入，沒有個人帳號。所有股東權限相同。
10. **多人共用。** 所有人看同一份資料，重新整理就同步。自己的操作會立即反映在畫面上。
11. **刪除與搜尋。** 刪除需確認；刪除的物件進回收桶（狀態篩選的最後一個選項），可以還原。搜尋見 3.1。
12. **直達連結。** 每個物件有自己的網址，可貼給其他股東；未登入者要先輸入共享密碼，登入後直接開啟該物件。

重複的網址：貼上的網址去掉 `#` 片段與 `utm_` 開頭、`fbclid` 參數後，若與倉庫中某個未刪除物件的來源網址完全相同，就直接開啟那個物件，不另外建立。除此之外不做任何去重。

## 6. 資料與技術架構

### 6.1 服務評估

| 服務 | 結論 | 理由 |
|---|---|---|
| Vercel（主機） | 保留 | 放網站與伺服器端程式 |
| Neon Postgres（資料庫） | 保留 | 多人共用的資料一定要有一個共用的儲存處。兩張小表，Free 方案足夠，閒置休眠後有連線會自動醒 |
| Vercel Blob（照片） | **刪除** | 不再儲存任何照片，封面直接顯示原站圖片 |

整個網站只用兩個服務：Vercel 與 Neon。Neon Free 為 US$0。Vercel 的方案見第 9 節。

### 6.2 技術選型

- Next.js（App Router）＋ TypeScript ＋ Tailwind CSS，以動工當下 `create-next-app` 的最新穩定版為準。
- 資料存取用 `pg` 與參數化 SQL，不用 ORM。
- 所有寫入都用 Server Action。沒有檔案上傳，所以不需要另外的上傳端點。
- Vercel Functions 區域設為 `sin1`（新加坡），Neon 也選新加坡。
- 全站回應帶 `X-Robots-Tag: noindex, nofollow`。
- 程式庫是公開的，不得出現密碼、`.env` 檔與真實物件資料。

### 6.3 資料表

程式裡「物件」的代號一律是 `item`。

**`items`（物件）**

| 欄位 | 說明 |
|---|---|
| `id` | uuid，主鍵 |
| `name` | 名稱，唯一必填 |
| `source_url` | 來源網址，可空 |
| `cover_url` | 封面圖片網址，可空 |
| `info` | 簡單資訊，一段文字 |
| `address` | 地址，供 Google Maps 連結使用 |
| `embed_ok` | 是否在右側嵌入原始網頁 |
| `status` | `new` 未討論／`pending` 待確認／`rejected` 不考慮／`shortlisted` 確定考慮 |
| `note`、`note_by`、`note_at` | 重要備註，以及最後由誰、何時更新 |
| `created_by`、`created_at`、`updated_at` | 建立者暱稱與時間 |
| `deleted_at` | 非空代表在回收桶 |

**`entries`（留言與狀態異動）**

| 欄位 | 說明 |
|---|---|
| `id`、`item_id` | |
| `kind` | `comment` 留言／`status` 狀態異動 |
| `body` | 留言內容 |
| `from_status`、`to_status` | 只有狀態異動使用 |
| `nickname`、`created_at` | |

Schema 寫在一個可重複執行、只增不減的 SQL 檔，在建置指令中自動套用，不需要人工進資料庫操作。

### 6.4 進出控制

- 環境變數 `SITE_PASSWORD`。未設定或少於 8 個字元時一律拒絕登入。
- 登入頁兩個欄位：共享密碼、暱稱。密碼在伺服器驗證。
- 登入後以 `httpOnly` 的 cookie 保存登入狀態 90 天。cookie 的值由共享密碼推導，所以換密碼並重新部署後，所有裝置自動登出。
- 每一個伺服器端的讀取與寫入都要先確認登入狀態。未登入時的回應不得包含任何物件資料。
- 資料庫只由伺服器存取，瀏覽器拿不到任何憑證。

### 6.5 貼網址時伺服器做的事

伺服器對貼上的網址發出一次請求，用來取標題、封面、描述，並判斷能否嵌入。基本限制只有四條：

1. 只有已登入的股東能觸發，一次貼上只讀一頁，不重試、不排程。
2. 只接受 `http`、`https`，拒絕 `localhost` 與 IP 位址形式的主機。
3. 逾時 6 秒，最多讀 1 MB。
4. 被對方擋下就停，不嘗試任何繞過。

讀取失敗時物件照樣建立。

封面圖片由瀏覽器直接向原站載入，不帶來源資訊（`referrerpolicy="no-referrer"`）。

## 7. 驗收標準

| 編號 | 驗收標準 |
|---|---|
| V1 | 未登入只看到登入頁。輸入正確的共享密碼與暱稱後進入倉庫，關掉瀏覽器再開仍是登入狀態。密碼錯誤被拒；未登入直接呼叫任何讀寫都被拒。 |
| V2 | 貼入一個 591 店面網址：幾秒內出現新物件，並帶入名稱與封面。貼入一個會擋機器的網址（例如樂屋網）：物件照樣建立並保留網址。 |

| V5 | 倉庫可在圖庫與列表間切換，都顯示名稱、封面（有才顯示）、簡單資訊、狀態。狀態篩選與搜尋可用，預設不顯示「不考慮」。 |

| V7 | 「開啟原始網頁」另開視窗；接著對另一個物件再按一次，沿用同一個外部視窗。 |
| V8 | 上一間／下一間可連續切換。X、Esc、瀏覽器返回鍵都能關閉，關閉後倉庫停在原本的位置。 |
| V9 | 四種狀態一鍵切換，留言區自動出現狀態異動。重要備註可編輯並顯示最後更新者與時間。留言顯示暱稱與時間。在預設篩選下把物件改成「不考慮」後，瀏覽區不會自己關掉。 |
| V10 | 有地址的物件顯示 Google Maps 連結並開啟該地址；沒有地址的不顯示。 |
| V11 | 刪除需確認；刪除的物件出現在回收桶，還原後備註與留言完整。 |
| V12 | 把直達連結給未登入的人：先要求共享密碼，登入後直接開啟該物件。另一位股東在另一台裝置重新整理後看到相同的資料。 |
| V13 | 手機上可以瀏覽倉庫、進入全螢幕詳細檢視、開啟原始網頁、改狀態、寫備註與留言。 |

另外，交付時 lint、型別檢查與建置必須通過。

## 8. 開發順序與上線

### 8.1 開發順序

一個階段，依序完成，每一步做完先自己驗證：

1. 專案骨架、資料表、登入。（V1）
2. 手動新增、編輯、倉庫的圖庫與列表、狀態篩選、搜尋。（V3、V5）
3. 右側瀏覽區：左右分割、上一間／下一間、關閉、直達連結、手機全螢幕檢視。（V8、V12、V13）
4. 狀態、重要備註、留言、Google Maps 連結、刪除與還原。（V9、V10、V11）
5. 貼網址新增：取網址、重複檢查、讀取標題與封面、嵌入判斷、嵌入與替代畫面、外部視窗。（V2、V4、V6、V7）
6. 用一支瀏覽器腳本把 V1–V13 走一遍，全部確認後回報。

**尚未驗證**

- 591 是否真的能在瀏覽器的框架裡正常顯示。目前只確認了回應標頭允許，見 4.4。
- 從 Vercel 的主機讀 591 是否拿得到標題與封面。先前只在另一個雲端位址測過。拿不到時物件照樣建立，手動改名稱即可。

**已知限制**

- 封面是外連原站的圖片，刊登下架後封面可能消失，屆時顯示名稱色塊。
- 去重只認清理後完全相同的網址。同一則刊登的手機版與電腦版網址會被當成兩個物件，由股東自行刪除其一。
- 重要備註以最後寫入者為準；兩人同時編輯時，後存的會蓋掉先存的。
- 留言送出後不能修改或刪除。
- 沒有即時同步，要重新整理才看得到別人的更新。
- 已嵌入的網站若日後改為禁止嵌入，右側會顯示瀏覽器的拒絕訊息；此時用「開啟原始網頁」，或在編輯裡關掉嵌入。
- 共享密碼沒有鎖定機制，安全性取決於密碼長度與是否外流。
